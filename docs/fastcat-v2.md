# FastCat v2 · Android 3.7.0

手机刷新获授权的订阅，选地区，在首页点「连接」。面板为每台获授权的设备下发一个逻辑节点，节点内含两个经过证书校验的 TLS 1.3 入口。使用者可以在「我的 → 工具设置 → FastCat v2 连接状态」刷新查看已观察到的 TCP 协议、UDP 状态和最近的分类错误。

通过链接明确选择的订阅会在重启后保持选中，登录账户仍可在后台刷新其自己的订阅缓存。最终真机包已验证重启后收到新的账户订阅，首页继续显示选定的单个 v2 节点；同一轮 TCP 和 UDP 业务均通过系统 VPN 到达网关。

| 业务 | HTTP/2 入口 | HTTP/3 入口 |
| --- | --- | --- |
| TCP，如 HTTPS 网页 | 每个目标连接新开 CONNECT 流，复用入口 TLS | 每个目标连接新开 CONNECT 流，复用入口 QUIC |
| UDP，如游戏及语音数据报 | 此入口不承载 UDP | 使用 CONNECT-UDP，数据报在协商了 HTTP Datagrams 的 QUIC 连接上传输 |

## 路径和连接池

手机在当前网络上用新请求比较两条 TCP 路径。每条路径记录最近五分钟内最多八个样本，结合建隧道成功率和收到首个隧道载荷的耗时。收到首个载荷前，使用 CONNECT 耗时。HTTPS 的第一个隧道载荷可能是目标网站的 TLS 握手消息；浏览器的网页首字节需要单独测量。连续浏览时复用的是到入口的连接，每个目标网站仍有自己的连接。

入口网络不可达时，新 TCP 连接可以尝试另一条路径，失败路径有 30 秒冷却。空闲时不发送探测流量，后续重采样使用新业务请求。证书、设备认证或目标连接失败按实际阶段返回，已发送的业务数据不会由客户端重放。Wi-Fi 或蜂窝路径改变时，旧连接池和统计失效，新请求重新选路。每个节点按需建立一条 H2 入口连接和一条 H3 入口连接，空闲回收时间分别为 30 秒和最多 60 秒。

同一个 Wi-Fi 上也可能突然丢失 UDP。复用中的 H3 连接若在发送新 CONNECT 后一秒仍没有回应，客户端才在同一连接上另外询问一次入口。并发请求共用这次检查。入口及时回答时，原请求继续等目标；入口检查也超时时，尚未发送业务数据的新 TCP 请求可改走 H2，新的 UDP 会话报告入口不可用。

## 凭证和密钥交换

在 `fastcat:auto grant` 中指定设备网关签发的设备记录 ID，每台设备得到两份独立的随机凭证。撤销后要导出名单、同步入口并重载，之后该设备的新 CONNECT 均被拒绝。同账户下别的设备可继续使用。已成立的隧道直到关闭或会话到期。旧版账户授权和新版设备授权分别管理；严格按设备管控的账户还需处理此前发放的账户凭证。

默认模式由 TLS 实现协商。设置 `tls-key-exchange: x25519` 或 `tls-key-exchange: x25519mlkem768` 可作严格对照。强制混合组时，不能协商到该组就返回失败。指定的组参与密钥交换，数据加密由协商的 TLS 1.3 密码套件完成。荣耀 Android 12 的手机回环握手实验每组 31 次，见 [实测握手耗时、收发字节和复测命令](../experiments/https-h2/TLS-BENCHMARK.md)。

H3 使用 [HTTP/3](https://www.rfc-editor.org/rfc/rfc9114.html)、[HTTP Datagrams](https://www.rfc-editor.org/rfc/rfc9297.html) 和 [CONNECT-UDP](https://www.rfc-editor.org/rfc/rfc9298.html)。通过 QUIC 原生 DATAGRAM 发送的载荷受路径可容纳的数据报大小限制。发送程序需能处理 UDP 丢包。

## 安卓真机验收

在荣耀 TFY-AN00（Android 12）上，从加密订阅导入一个地区节点，再从首页连接系统 VPN。测试网关和两个 HTTP 目标位于同一 Wi-Fi 的电脑上，服务端记录可区分手机直连和经网关转发。荣耀自带浏览器分别打开两个域名，两次请求的唯一标记均在网关后的目标收到。

独立 Android 应用经过系统 VPN 向两个目标发出 25 次 HTTP 请求，全部核对响应成功。自动选路下，首个请求首字节为 54.85 ms，随后 12 次顺序请求的中位数为 23.10 ms，另 12 次四路并发请求的中位数为 69.76 ms。三次 UDP 测试的载荷分别为 20、141、262 字节，返回内容与数据报边界均相符。这些数字是手机到局域网目标的结果。

另一次关闭 H2，启动全新的 H3 入口，用独立于业务流量的 USB 控制通道协调起跑。开始计时后 154.7 ms，网关才收到首个 QUIC Initial，证实本轮计入建立新连接。手机测得首个 HTTP 响应首字节为 249.68 ms。随后交替访问两个目标，顺序 12 次均成功，P50 为 22.01 ms，P95 为 122.95 ms。四路并发 12 次均成功，P50 为 20.34 ms，P95 为 27.11 ms。冷启动只有一个样本。

在已通过 H3 请求网页和 UDP 后，保持 Wi-Fi 连接，打开备用 H2，将 H3 服务进程暂停并保留 UDP 端口。网关没有发回 QUIC 数据。两个新网页请求均经 H2 抵达目标，首个首字节为 2,169.31 ms，下一个为 17.66 ms。三个新的 UDP 标记均未到达目标。手机连接状态页显示「最近 TCP 连接 · HTTP/2」「UDP · 不可用」「UDP · 入口网络不可达」。恢复 H3 后立即尝试的 UDP 仍超时，44.7 秒后的下一组 3 个均成功，中间没有持续测试。

仅让快猫和测试应用进入 VPN，锁屏 106.6 秒，两个受控目标均未收到新请求。H2 连接在锁屏 7.3 秒后关闭，在第 47 秒又建立了一条。网关观察到的 QUIC 载荷是手机发出 4,524 字节、收到 15,132 字节。手机唤醒后的三次 UDP 回显均成功。空闲回收时间从最后一次活动起算，整机锁屏时仍有其他网络活动。Android VPN 服务运行时会持有部分唤醒锁，且会执行健康检查；本轮手机通过 USB 供电，无法由这些流量数字算出待机耗电或相对 v1 的节电幅度。

服务端和面板的安装、设备凭证发放以及撤销流程见 [Linux 部署与回滚](fastcat-v2-linux.md)。
