# FCN v3 优化复测与 ECH 验收

优化后在 `zlhk.fastcat.lol` 复测，FCN v3 与 TUIC 各 **174/174** 次校验成功。预定的八项性能门槛通过七项，四路并发首字节 P50 仍超限。严格 ECH 与入口 DoH 已通过安卓公网轮换和故障测试。

## 性能优化

连接准备可独立于业务请求提前启动。同批调用等待同一个有上限的建连结果，单个调用的取消不会中断其他请求。预建不发送 CONNECT，也不拨目标。下行转发复用 64 KiB 缓冲，读取到数据后立即写入 HTTP/3 流。小回复无需等满缓冲。

2026-11-25 14:20–14:24（北京时间）在同一荣耀手机、Wi‑Fi、香港服务节点和同一校验源上做 54 批次对照。常规测试使用按需建连，预建单独评估。两条入口共用证书及目标、使用各自实现的 BBR，采样次序与第一阶段相同。

|---|---:|---:|---:|
| 冷启动首字节 P50 / P95 | 314.7 / 1245.3 ms | 334.2 / 1316.1 ms | −5.8% / −5.4% |
| 连续请求首字节 P50 / P95 | 105.0 / 213.4 ms | 102.3 / 202.5 ms | +2.6% / +5.4% |

下载吞吐为六轮整批速率中位数，含建连、业务和清理。TUIC 单路中位数从上一轮的 18.03 Mbps 变成这一轮的 6.49 Mbps，轮次差异明显。单路和四路下载的成对比值中位数分别为 118% 和 126%。本轮达标，现有数据不足以把提升全部归因于缓冲改动或外推至其他网络。

额外六组交替对照中，按需建连 24/24，预建 20/24。一组预建在 8 秒预算内未建立连接，四个后续请求都保留为失败。成功批次首字节 P50 的中位数为 717 ms 对 154 ms，预建自身耗时中位数 251 ms。按需批次完整耗时中位数 1814 ms，成功预建批次算上预建为 1454 ms。预建保持可选，首个业务的等待可以提前，但建连耗时和失败仍需计入评估。

## ECH 与加密 DNS

严格配置下客户端通过固定的 DoH bootstrap IP 建立受证书保护的 HTTPS，请求 HTTPS、A 和 AAAA 记录。HTTPS 记录必须带可用的 ECH 配置，外层名与内层名必须不同。缓存遵从记录 TTL 及设置的上限。QUIC 对端地址来自 DoH，服务器只在确认 ECH 被接受后开放 CONNECT。收到明确 ECH 拒绝时，客户端仅重新向 DoH 刷新一次，只有配置发生变化才重新握手。不会把内层域名作为明文 SNI 重试，也不以系统 DNS 或配置里的固定地址代替 DoH。 [ECH 标准](https://www.rfc-editor.org/rfc/rfc9849.html) · [DoH 标准](https://www.rfc-editor.org/rfc/rfc8484.html)

公网验证使用内层 `zlhk.fastcat.lol`，外层 `ech-public.fastcat.lol`，DoH 名称 `entry-dns.fastcat.lol`。使用固定 bootstrap 和独立测试证书，在安卓测试工具中验证各自域名。HTTPS 记录由受控 DoH 测试源返回，未修改公网 DNS 记录。

| 场景 | 请求结果 | 抓包中的 QUIC ClientHello |
|---|---|---:|
| 初始 ECH / 新旧密钥重叠 | 正常转发 | 各 1 条外层 SNI + ECH |
| 旧密钥退役，DoH 仍给旧配置 | 拒绝，刷新无变化后结束 | 1 条外层 SNI + ECH |
| 旧配置被拒绝，DoH 刷新给新配置 | 自动恢复，最终校验成功 | 2 条，均为外层 SNI + ECH |
| HTTPS 记录缺 ECH / 配置损坏 / 内外层同名 | 拒绝 | 0 |
| DoH 返回 503 / DoH 证书不受信任 | 拒绝 | 0 |
| 明确使用外层名的无 ECH 对照 | QUIC 握手可完成，CONNECT 拒绝 | 1 条明文外层 SNI |
| 服务端轮换文件损坏 | 保留上一有效密钥，请求成功 | 1 条外层 SNI + ECH |
| 恢复有效配置 | 请求成功 | 1 条外层 SNI + ECH |

初测发现一次业务成功但抓包未收齐，以及一次重叠阶段 DoH 超时。从两次失败中均无法提取可验收的 QUIC 握手样本，原始结果保留。复测改为即时抓包并延迟停止采集。DoH 测试源也将 TLS 握手移入各自处理线程，避免串行阻塞接入。初始、重叠、退役、刷新四项再次执行并通过。

全部已完整解出的 **10 条严格模式握手** 都是外层 SNI 带 ECH，明文内层 SNI **0 条**。使用公开的 QUIC Initial 密钥推导和认证解密解析 ClientHello，未解密业务数据。真正接受 ECH 由客户端和服务端的 TLS 状态检查加上业务校验确认。服务端抓包覆盖限定入口端口，不能用它证明安卓其他进程从未发出明文 DNS。当前 FCN v3 入口解析代码只有经 TLS 验证的 DoH 路径，故障测试确认未再拨 QUIC 入口。 [QUIC Initial 密钥规范](https://www.rfc-editor.org/rfc/rfc9001.html#section-5.2)

本地集成测试另外验证了密钥轮换时已有连接保留，退役旧配置后新建连接触发一次刷新，以及旧连接仍能新建业务流。竞态测试、Go vet 和统计脚本测试均通过。临时端口和测试凭证已清理，服务端保留私有的限定端口原始抓包。填充仍关闭，正式 App 和面板集成留在后续工作。
