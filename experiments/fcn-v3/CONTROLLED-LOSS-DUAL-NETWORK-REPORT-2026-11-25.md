# FCN v3 受控丢包与安卓双网络复测

2026 年 11 月 25 日。先在服务器两个专用 Linux 网络命名空间内完成四路下载，再在同一台安卓上按 Wi‑Fi、蜂窝顺序运行 UDP。每项都对照现有 FCN v3、仅开启自适应写入的 FCN v3 和 TUIC v5，各组交替出场。所有测试使用临时凭证、统一测试证书和确定性源站。

## 四路正文

每批四路各 1 MiB，单路 25 秒上限。双向各配置 50 ms 延迟、20 Mbit/s 限速，预检链路稳定后实测往返约 100 ms。各配置六轮，保持上行随机丢包配置为零，逐轮只调整下行 netem 随机丢包概率。

| 下行配置 | qdisc 观测丢弃比 | 现有 FCN v3 吞吐 / 正文间隔 P95 | 自适应 FCN v3 吞吐 / 正文间隔 P95 | TUIC v5 吞吐 / 正文间隔 P95 |
| --- | ---: | ---: | ---: | ---: |
| 0% | 0.00% | 15.15 Mbps / 88 ms | 15.18 Mbps / 86 ms | 15.17 Mbps / 87 ms |
| 2% | 0.87% | 14.79 Mbps / 352 ms | 14.54 Mbps / 331 ms | 14.54 Mbps / 283 ms |
| 8% | 4.14% | 13.69 Mbps / 366 ms | 13.43 Mbps / 373 ms | 13.04 Mbps / 332 ms |

表中吞吐为整批有效吞吐中位数。正文间隔 P95 是对每条流最大无进展间隔取 P95。配置概率与 qdisc 统计粒度有差异，后者用各对照块发送和丢弃计数变化计算，包含协议控制流量和分段影响。每档上行 qdisc 丢弃计数均为零。随机序列作用于经过队列的流量，各协议的单条连接经历的具体丢包序列可以不同。

**216/216 条流校验通过，旧的 25 秒正文卡住未复现。** 随机丢包使正文无进展间隔明显加长。配置到 8% 时，现有 FCN v3 和自适应版分别记录 1,703 和 1,689 次 QUIC 丢包判定，两组都有探测超时计数更新。该档最慢的正文间隔出现在 TUIC，约 560 ms。全部源站写入完成，最长写入回执约 16.46 ms。QUIC 丢包判定可包含乱序。

三档按轮配对，自适应版与现有版的吞吐比中位数约为 1.001、0.986、1.013。两版在固定链路上接近，支持继续保留 64 KiB 固定缓冲。旧公网停顿的触发条件仍待复现。这轮验证的是随机丢包效应。

## UDP 回程

同一台安卓分别在 Wi‑Fi 和蜂窝网络上各跑六轮。每轮三组交替出场，固定客户端、服务器端口、报文大小序列和每包 1.5 秒等待窗口。每轮每组 28 包，每网络每组 168 包。Wi‑Fi 和蜂窝分别确认默认网络已由系统验证，36 个测试块的前后网络身份都稳定。先 Wi‑Fi 后蜂窝，公网时段随之变化。

| 组别 | Wi‑Fi 正确回显 | 蜂窝正确回显 | Wi‑Fi 成功 RTT P95 | 蜂窝成功 RTT P95 |
| --- | ---: | ---: | ---: | ---: |
| 现有 FCN v3 | 162/168 (96.4%) | 164/168 (97.6%) | 220 ms | 178 ms |
| 自适应 FCN v3 | 149/168 (88.7%) | 138/168 (82.1%) | 297 ms | 252 ms |
| TUIC v5 | 130/168 (77.4%) | 159/168 (94.6%) | 376 ms | 230 ms |
| 合计 | 441/504 (87.5%) | 461/504 (91.5%) | — | — |

蜂窝阶段总超时从 63 降为 43，变化主要来自 TUIC，现有 FCN 小幅改善，自适应版这一组下降。自适应开关实际只影响 TCP 写入，UDP 组间差值不能作为该开关的效果。该结果适用于这台手机及这两段公网路径。

- **回程候选**：Wi‑Fi 58 次、蜂窝 38 次，合计 **96/106** 次超时。源站已回显，服务端按成功样本的长度和时间范围找到唯一出站候选，但安卓套接字没有相同指纹。其余 **10** 次请求未到源站，两种网络各 5 次。
- **安卓队列**：36 个测试套接字启用溢出观测，均未收到丢弃通知。该内核通知随后续成功交付的数据报附带，因此没有通知不能证明没有队列丢弃，尤其是尾部丢弃。
- **抓包交叉核验**：两种网络下安卓实际读到的 2,536 个加密数据报均可匹配服务端出站指纹，服务器抓包报告内核丢弃 0。未匹配的出站数据报包含控制报文。回显与加密报文的关联依据时间和长度，无法继续把超时拆到无线链路、运营商路径或手机内核各段。

原 Wi‑Fi 开关恢复后，手机一度仍使用蜂窝。唤醒刷新扫描后，复核手机已重新连回原来保存的 Wi‑Fi，系统验证通过，Wi‑Fi 与蜂窝数据开关均与测试前一致。临时端口、网络命名空间、原始抓包、测试文件和一次性凭证已清理。核心和诊断工具的竞态测试与 vet 通过。
