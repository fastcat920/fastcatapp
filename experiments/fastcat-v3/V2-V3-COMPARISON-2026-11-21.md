# FastCat v2 / v3 安卓同网对照

2026-11-21，当前连接的荣耀安卓（A3GMVB2110006859），物理 Wi-Fi 网络前后均为 network 171。
使用一个独立对照程序运行两套客户端核心，外层校验同一张 zlhk.fastcat.ink 证书，
连接同一台香港服务器的独立端口（v2 19442，v3 19443）。入口采用固定 IP，
未启用 ECH 或入口 DoH。目标固定为 example.com:443，验证 HTTPS HEAD 返回200。

两套服务端统一使用 Go 1.27.3。安卓同一个对照程序使用 Go 1.26.2。每轮交换
v2/v3先后，也交替H2/H3顺序。两服务在正式测试前同时重启。

## 正式结果

每组20次。P50/P95只计算成功请求，采用最近秩分位数，20次的P95为第二慢值。
冷启动从建立全新客户端开始计时，包括入口TLS、v3握手、目标OPEN、目标TLS及首字节。
复用组在预热后使用现有连接。并发组在现有连接上每批同时发4个请求，共5批。
每条业务均重新建立目标TLS。首字节时间不包含完整响应头读取，但成功需核对HTTP 200。

| 场景 | 承载 | v2 成功 | v2 P50 / P95 | v3 成功 | v3 P50 / P95 |
|---|---|---:|---:|---:|---:|
| 冷启动 | H2 | 20/20 | 2020 / 4212 ms | 20/20 | 2596 / 5722 ms |
| 冷启动 | H3 | 20/20 | 1296 / 1791 ms | 19/20 | 1926 / 4128 ms |
| 连接复用 | H2 | 20/20 | 1048 / 3131 ms | 20/20 | 731 / 1728 ms |
| 连接复用 | H3 | 20/20 | 498 / 816 ms | 20/20 | 593 / 842 ms |
| 4路并发 | H2 | 20/20 | 1335 / 4105 ms | 20/20 | 843 / 1016 ms |
| 4路并发 | H3 | 20/20 | 721 / 1127 ms | 20/20 | 684 / 878 ms |

正式样本共239/240成功。v2为120/120，v3为119/120。
v3 H3冷连接出现一次QUIC连接超时，计入失败；未用重试替换失败样本。预热另有4次，均成功。

## 分阶段观察

冷启动的入口建立中位数，H2为v2 1009 ms、v3 1583 ms；H3为v2 665 ms、v3 1132 ms。
v3在入口阶段增加了Noise认证及会话确认，实测入口耗时也更高。阶段中位数不能直接相加。
H2复用组的目标TLS耗时也有波动，因此总首字节差异不能全部归因于协议本身。

v3本轮收益最明显的是H2复用和并发；H3的冷启动及复用仍慢于v2。并发H3的差异较小。
本次不足以证明v3总体更快，结果不适用于其他网络或目标。

## 限制与复核

两种承载分别只覆盖当前Wi-Fi、单一目标和单次时段，端口不同。未测试吞吐、耗电、
跨网、原生UDP或抗识别性。v3为独立原型，客户端UI和面板尚未接入。

先前还做过一轮服务端Go版本不同的预跑（v2 1.27.3，v3 1.26.2），正式样本240/240
成功。该轮保留为preliminary数据，不与统一版本的结果合并。
