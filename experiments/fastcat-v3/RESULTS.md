# FastCat v3 首个原型验收

2026-11-20，在独立公网入口和连接的荣耀安卓真机验证。服务端为临时 Linux
进程，客户端为安卓独立程序。当前快猫 App 的节点列表及 VPN 协议尚未接入 v3。

## 通过项目

| 项目 | 结果 |
|---|---|
| 规范测试向量 | Go实现与Python参考向量的Noise消息、握手摘要及加密记录一致 |
| H2/H3并发与流控 | 每种承载8条流、每流600000字节，双向echo一致 |
| 取消后的额度回收 | 每种承载24条流各写256KiB后取消，新流仍能收发 |
| 密钥更新 | 同一会话更新发送密钥后，继续完成目标HTTPS请求 |
| UDP关联 | 空数据报、8字节、1024字节echo一致，1025字节发送被拒绝 |
| 防重放和承载绑定 | 重复CLIENT_INIT及错误TLS exporter被拒绝 |
| 认证拒绝 | 两种公网承载均拒绝错误凭证、公钥及TLS域名，共6种失败组合 |
| 真实网站 | 安卓两轮probe共28次HTTPS HEAD成功；本地CONNECT代理额外3个网站返回200 |
| 本地质量检查 | macOS race检查、go vet、安卓真机协议测试通过 |

## 公网探针耗时

以下为安卓首轮，各用一个已认证会话。握手包括入口TLS与Noise；网页首字节
从OPEN目标开始，含目标TLS，排除入口会话握手。每组仅3次，不能估计P95。
安卓静态程序使用固定入口IP并校验zlhk.fastcat.ink证书，显式加载公共CA bundle。

| 承载 | 会话握手 | 三次网页首字节 |
|---|---:|---|
| H2 | 1465 ms | 828 / 966 / 1197 ms |
| H3 | 1809 ms | 984 / 1111 / 1443 ms |

最终二进制复核的H2/H3会话握手分别为4004 ms和1772 ms，存在明显网络波动。
此前Mac首次H2冷连接有一次8秒截止，重新测试成功。未据此调整协议超时或宣称
性能优于v2。完整结构化输出见results.json。

## 实现边界与修复

原型开发中修复了并发OPEN发送乱序、正常半关闭误重置、关闭连接竞争、取消流
消耗会话额度不回收的问题。规范向量中max_datagram从1200更正为1024并重新生成。

原生UDP承载、ACK/重传、会话恢复票据、多优先级调度、数据报过期调度、面板授权
与计量均未完成。当前UDP业务帧走可靠承载流，实时UDP性能需要独立评估。

本轮没有重新安装安卓App，也没有做协议识别概率实验。测试后清理临时服务和
手机测试凭证，手机恢复原VPN。v2生产节点配置未修改。
