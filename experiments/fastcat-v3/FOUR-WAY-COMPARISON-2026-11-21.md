# CatNode VLESS / Trojan 与 v2 / 最新轻量版安卓同网对照

日期：2026-11-21。

## 结论

本轮短请求优先选择v2：H2连续请求中位数490.4ms，H3冷启动中位数930.6ms；两条路径各60/60成功。VLESS Vision和Trojan各59/60。轻量版H3在并发阶段出现12次已关闭连接错误，不能只用其成功样本的P95判断性能。吞吐样本每组仅一次、波动很大，不能据此给四类协议做稳定排名。

## 实际测试组合

| 路径 | 服务端 | 传输与安全配置 |
|---|---|---|
| VLESS Vision | CatNode实际V2Core及锁定的Xray 26.10.31 | TCP + TLS + xtls-rprx-vision；VLESS额外加密关闭；未启用REALITY/WS/gRPC/Xray mux |
| Trojan | 同一CatNode V2Core | TCP + TLS；原生Trojan，未启用WS/gRPC或额外Shadowsocks层 |
| FastCat v2 H2/H3 | 上轮优化后的CatNode v2独立测试入口 | H2/TCP/TLS1.3 或 H3/QUIC/TLS1.3，令牌认证；固定载体，不经过自动选路 |
| 最新轻量版 H2/H3 | 与上一轮相同的独立原型 | v3-light-fast / IndependentPipelined；Noise会话与轻量独立流 |

四组外层使用同一域名zlhk.fastcat.ink及有效证书，严格验证，入口固定191.223.214.8；本轮没有ECH/DoH/REALITY，也没有前置。VLESS和Trojan逐请求观测均为TLS1.3（0x0304）和TLS_CHACHA20_POLY1305_SHA256；VLESS ALPN空，Trojan ALPN为h2。Trojan宣告h2不代表它在使用HTTP/2承载，其数据协议仍是原生Trojan。未强制所有实现使用同一密码套件，因此这是实际实现组合对照，并非固定密码套件的微基准。

VLESS/Trojan调用CatNode的V2Core.Start/AddNode/AddUsers，并保留其自定义dispatcher、计数与limiter流程；使用临时不限速用户，离线注入节点信息，不连接生产面板，不计入用户套餐。使用CatNode go.mod锁定的Xray分支；模块与二进制哈希见metadata。v2/轻量版使用原有独立测试核心，未修改协议实现以重跑数据。

## 方法

同一安卓A3GMVB2110006859、同一Wi-Fi与香港服务器。测试前后及延迟组结束时物理默认网络均为171。测试期间手机原VPN断开，运行独立原生核心程序；不经过正式App的TUN、订阅或界面，因此结果不是正式App端到端延迟。

先通过CatNode本地双入口启动自检及24条公网预检，再进行正式交替测试。每条路径冷启动20次、连续请求20次、四路并发5批共20次，六条路径共360次正式请求，另有18次连接池预热。目标example.com:443，目标TLS验证与HEAD 200通过才算成功；逐轮交换载体及版本顺序。

H2/H3连续组轮换3个长连接池；VLESS/Trojan虽复用适配器对象，每次业务仍新建TCP/TLS连接，不称为入口连接复用。四路并发中H2/H3同池共用一条入口，VLESS/Trojan各建四条入口。区别属于此次实际配置，不能外推到启用mux、REALITY或其他传输的组合。

VLESS/Trojan的目标建立发生在lazy协议头/内层TLS期间，v2则可能在CONNECT响应前完成。故entry_us等分段不能横向当成同一阶段；下表统一比较从业务开始到目标响应首字节的总时间。后端DNS和默认转发策略保留各自实现，未固定目标CDN地址。

## 首字节结果

单位ms，P50 / P95；仅统计成功请求，P95为最近秩。每场景20次，成功总数不含预热。

| 路径 | 成功/总数 | 冷启动 | 连续请求 | 四路并发 |
|---|---:|---:|---:|---:|
| FastCat v2 · H2 | 60/60 | 1385.1 / 3187.4 | 490.4 / 887.9 | 998.4 / 2566.4 |
| FastCat v2 · H3 | 60/60 | 930.6 / 2562.6 | 655.4 / 1189.3 | 1094.6 / 2092.7 |
| 最新轻量版 · H2 | 60/60 | 1323.2 / 3201.6 | 1020.1 / 3789.2 | 1264.0 / 1961.5 |
| 最新轻量版 · H3 | 48/60 | 1377.5 / 2265.3 | 759.1 / 1384.6 | 1559.2 / 1632.6 |
| VLESS + TCP + TLS + Vision | 59/60 | 1468.4 / 3421.0 | 1503.1 / 5460.3 | 1381.1 / 3188.6 |
| Trojan + TCP + TLS | 59/60 | 1563.4 / 2960.2 | 1318.6 / 3209.4 | 1098.2 / 5275.1 |

轻量版H3并发仅8/20成功，上表该格分位数来自这8个成功样本，不含12次失败；不能据此认为其P95优于v2。

### 失败与连接空闲问题

- VLESS Vision：冷启动1次目标TLS阶段EOF，不能仅凭EOF确定是目标、转发还是传输原因。
- Trojan：并发1次目标TLS握手超时。
- 轻量版H3：并发12次 `entry: use of closed network connection`。
- v2 H2/H3、轻量版H2：正式请求均成功。

轻量版H3三个池首次失败前，距此前最后成功请求结束约41.85秒、40.19秒、59.99秒；源码MaxIdleTimeout为30秒，当前原型没有在会话失效后为新业务自动重建。时间及代码与空闲关闭一致，属于较强推断；未采集底层运行时关闭cause，不能写成已最终定位。原始失败保留，未重试替换。新的吞吐客户端均重新建立会话，与这些失效池分开计量。

## TLS内层吞吐对照

控制目标为同服务器19445端口的TLS1.3回显服务，严格验证zlhk.fastcat.ink证书。所有路径在隧道内建立同样的目标TLS，再发送数据，使VLESS Vision能够看到真实的内层TLS握手。该测试为TLS保护的全双工回显，不等同真实HTTP文件下载或总线速。

每条路径单流和四路各一组，准备入口与目标TLS后传输约10秒；按实际收到并通过模式校验的解密数据计下载有效Mbps，四路为合计，上传accepted字节不当作送达字节。共12组、30条流，均收到有效数据且未提前报错。这不代表固定大小文件全部完成。

| 路径 | 单流 下载Mbps | 四路合计 下载Mbps |
|---|---:|---:|
| FastCat v2 · H2 | 10.799 | 0.262 |
| FastCat v2 · H3 | 0.537 | 0.300 |
| 最新轻量版 · H2 | 4.911 | 12.592 |
| 最新轻量版 · H3 | 0.210 | 0.297 |
| VLESS + TCP + TLS + Vision | 0.550 | 6.303 |
| Trojan + TCP + TLS | 0.210 | 1.599 |

v2 H2单流本次较高，轻量版H2四路本次较高；v2 H2单流与四路有明显反转。每格只有一次且未隔离公网丢包、路径与拥塞状态，不据此宣称任何协议稳定吞吐更高。应以更多轮交替、交换测试端口、多网络及单向下载继续复核。不同组的内存/分配数来自共享测试进程且没有独立基线，不用于给正式App做资源或耗电排名。

## 工具与可复现性

协议实现保持不变。延迟和吞吐进程分别使用记录的测试工具哈希：吞吐版增加BulkTLSName选项以统一目标TLS，延迟逻辑及协议客户端相同；在延迟进程运行期间原子替换路径只影响后续新进程，未改变已运行进程。两阶段哈希分别记录在client-phase-hashes和metadata。吞吐后端TLS1.3已单独验证。

测试工具的跨读取边界/损坏校验及六路径矩阵测试通过，相关Go vet通过。初次实验配置将CatNode额外加密字段填为none，启动前被拒绝；改为空值后通过本地及公网预检，没有将配置错误计入正式协议失败。

可复查源码：`core/tools/fastcat-v3-compare`；CatNode构建包装位于`harnesses/catnode_four_way.go`，必须在CatNode模块内构建以使用同一依赖；`harnesses/run_four_way.py`为整理后的复现脚本，要求预先构建所列二进制、连接指定安卓及SSH会话。`harnesses/tls_echo.py`为本轮控制目标。复现脚本每次生成临时授权，不能使用它操作生产端口。原始记录与汇总见同目录 `four-way-2026-11-21-*`。

## 清理与适用范围

临时19442/19444/19445/19446/19448服务、远端二进制及临时凭证均已清理；手机原VPN及stay-on设置0恢复。生产443/18447及正式App未替换。

这是单台安卓、单个Wi-Fi、单服务器、单目标的当轮结果。短请求更支持v2当前实现，轻量版需优先补会话失效后的新业务重建；不能由这次测试推断所有VLESS/Trojan组合、长期稳定性、耗电或抗识别能力。
