# FastCat HTTP/2 独立测试版

一个程序可以运行客户端或服务端。客户端把多个目标 TCP 连接映射到同一条 TLS 1.3 连接上的独立 HTTP/2 CONNECT 流。测试时不需要 Flutter、手机、面板或 v1 服务。当前版本只代理 TCP。

## Mac 上一条命令自测

在本目录运行（需要 Python 3、OpenSSL 和已构建的本机程序）：

```sh
python3 smoke.py --binary ./artifacts/fastcat-h2-macos-arm64
```

脚本启动临时回环入口、客户端和回显目标，自动生成短期测试证书和随机令牌，结束后清理。若本机装有 Go 1.26 或以上，也可以直接运行 `python3 smoke.py` 从源码自测。要与已有 v1 在同一目标、相同载荷下对照，可以加 `--v1 ../https-tcp/artifacts/fastcat-https-macos-arm64`。本地计时包含进程间转发和目标响应，不包含公网往返、网页渲染或手机 VPN 开销。

## 自有 Linux 节点与 Mac 对测

Linux 使用与服务器架构匹配的程序，下例为 x86_64。在两个终端各自安全输入**同一个新的测试令牌**（24 至 512 个可见 ASCII 字符，无空格）。下面的输入方式适用于 Bash 或 Zsh，令牌不会进入命令历史。Mac 和 Linux 上程序的参数相同。

```sh
read -rs FASTCAT_H2_TOKEN
export FASTCAT_H2_TOKEN
```

在 Linux 上从含程序的目录执行。示例用独立的 TCP 18444 测试端口和已有域名证书。服务进程需要读取证书、私钥，客户端需要能到达该端口。

```sh
./fastcat-h2-linux-amd64 server -listen 0.0.0.0:18444 \
  -cert /etc/letsencrypt/live/zlhk.fastcat.ink/fullchain.pem \
  -key /etc/letsencrypt/live/zlhk.fastcat.ink/privkey.pem
```

在 Mac 的实验目录运行客户端，用另一个终端执行 curl。保持客户端运行，后续 HTTPS 请求可继续复用入口的 TLS 连接。curl 正常校验目标网站证书，快猫客户端独立校验入口证书。

```sh
./artifacts/fastcat-h2-macos-arm64 client \
  -entry zlhk.fastcat.ink:18444 -listen 127.0.0.1:18081
```

```sh
curl --noproxy '' --proxy http://127.0.0.1:18081 https://example.com/
```

本地代理只接受 HTTP CONNECT，普通 HTTP GET 代理请求返回 405。要转发任意 TCP 程序，可在客户端命令加 `-target 目标主机:端口`，此时本地端口直接转发字节。两种本地入口均须绑定数值回环地址。测试 CA 用 `-ca 文件.pem` 指定，按 IP 连接但证书签给域名时可加 `-server-name 证书域名`。服务端的 `-allow-private-targets` 仅供回环监听的实验。

### 在同一条公网线路上对照 v1 和 HTTP/2

Linux 上同时运行现有 v1 服务（TCP 8443）和上述 HTTP/2 测试服务（TCP 18444），确保 Mac 能访问这两个端口。下面的命令会在 Mac 上启动并清理两个临时客户端。若 Mac 正在使用系统 VPN，两边的结果都可能包含该 VPN 的开销。

```sh
python3 compare_remote.py
```

根据提示输入 v1 与 HTTP/2 各自的令牌，输入时隐藏。默认通过两个入口请求快猫 App 使用的相同 HTTPS 204 测试地址。每个入口的首次请求单列，之后各做 20 次请求，每轮交换谁先测。两个客户端持续运行，每次请求都重新建立到目标网站的 TLS 连接。汇总统计成功数、失败数，以及成功请求首字节时间的中位数和 P95。这个时间包含入口、目标 TLS 和目标响应；单次失败应结合终端显示的客户端错误诊断。

用 `--rounds 50` 可增加样本。用 `--url https://自己的测试域名/小文件` 可改用自有的稳定目标，要求返回 2xx。自定义入口用 `--v1-entry 主机:端口 --h2-entry 主机:端口`。不同端口可能受到不同网络策略影响。该脚本用于比较当前部署在这条线路上的体验。

## 协议与连接行为

- 先校验证书链、域名、TLS 1.3 和 ALPN `h2`，再发送带目标 `:authority` 的 CONNECT。凭据位于 `Proxy-Authorization: Bearer …`。收到 200 且目标已连接后才发送业务字节。目标与网关分别寻址。
- 每个客户端按需打开一条到入口的连接，独立流共享握手，空闲约 30 秒后允许回收。重置一条流不会关闭其他流。下一次新建隧道可重新拨号，已经交付的应用字节不作跨连接重放。TCP 丢包仍可能让该物理连接上的多条流同时等待。
- 客户端先关闭写方向时，服务端会向目标发送 FIN，并继续转回延迟到达的响应。目标先发 FIN 时，Go HTTP/2 服务端在发送剩余响应后结束该流；依赖此后继续上传的特殊 TCP 协议应使用 v1。
- 默认仅允许公网目标，检查全部 DNS 应答后直接连接已验证 IP。默认每实例最多 128 条活动隧道，单条的绝对生命周期为 30 分钟。入口证书在进程启动时加载。
- TLS 和 HTTP/2 使用 Go 标准库。实际 TLS 参数由双方协商。本版没有单独承诺 ML-KEM、移动端耗电、吞吐增益或流量识别效果。

### 设备令牌

单机实验使用环境变量 `FASTCAT_H2_TOKEN`。多设备测试可给服务端传 `-tokens-file /绝对路径/device-tokens`，文件每行一个独立的随机令牌，仅授权服务进程读取。客户端仍只填写自己的令牌。更新文件后向这个测试服务进程发送 `SIGHUP` 即可重载；建议先写临时文件，再在同一目录原子替换。删除的令牌会在下一条 CONNECT 时被拒绝，即使设备仍在复用原先的 TLS 连接。已建立的流可继续到关闭或超时。空文件撤销全部新连接权限，载入错误保留上一份有效配置。

### 故障定位

远端 CONNECT 返回 407 表示设备认证失败，403 表示目标被策略拒绝，400 表示目标格式无效，502 表示目标解析或连接失败，503 表示达到并发上限。本地 HTTP 代理会向 curl 报告 502，具体上游错误可在快猫客户端终端查看。服务端会为每个实际承载请求的 HTTP/2 连接记录一次 `entry negotiated=h2`。入口 TCP、证书或 ALPN 失败均发生在 CONNECT 之前。相同 IP、端口同时失去可达性时，单次超时无法确定原因。

## iPhone 同机对测

iPhone 测试版与 Mac 命令行共用 HTTP/2 客户端实现。进入「我的 → 工具设置 → 新协议测试节点」，选择「HTTP/2」。核对域名和端口 18444，在手机上输入对应设备令牌，点「保存节点 → 使用测试配置」，回首页连接。v1 的测试配置单独保存在原来的 8443 节点里。

- 两个节点都已保存时，连接其中任一个。在「对照目标」选择 Google（默认，`www.gstatic.com/generate_204`）或 Cloudflare（`cp.cloudflare.com/generate_204`），点「同网对照 v1 / HTTP/2」。保持当前网络不变并让快猫留在前台。一次对照固定访问所选网站，每个节点的首个请求单列，随后交替测试 20 轮，每轮交换先后顺序。成功须直接收到目标站的 HTTPS 204。日常流量仍由当前选中的配置处理。
- 对照结果记录实际入口连接复用情况、入口 TCP（含域名解析）、入口 TLS、CONNECT 到目标接通、目标网站 TLS，以及发出请求后等待目标首字节的时间。复用已有入口时不会再计一次握手。完整隧道建立耗时包含其内部的入口握手及 CONNECT。各阶段中位数来自不同请求；分析长延迟时，可查看同一条最慢成功请求的分段记录。手机未观测到的阶段留空。
- VPN 已连接时回到此页，点「测连续请求」。核心通过指定节点向与 Mac 公网对照相同的 HTTPS 地址发出 GET，请求新建到目标站的连接。只有有效的 HTTP 204 响应计入成功。首个请求单列，后面 20 次中成功样本统计首字节 P50 和 P95。后台可能已为节点测速，因此本轮第一个请求可能使用已经建立的入口连接。
- 点「测切网恢复」，先等切网前的请求成功，再按屏幕提示切换 Wi-Fi 和蜂窝网络。显示的恢复时间从 App 观察到系统网络类型变化算起，包含后续重试和收到成功响应的时间。在控制中心停留或系统暂停 App 可能影响这个数值。也可保持 VPN 开启，从一个 Wi-Fi 切到另一个 Wi-Fi 后点「测连续请求」检查可用性；这种方法测量的是切换完成后发起的请求。
- 如需 v1 基准，选择 HTTPS v1，点「使用测试配置」并确认首页已经连接，在相同网络重复测试。两次操作间若使用「恢复原配置」，可回到测试前的订阅。

Apple PacketTunnel 在物理接口改变时关闭旧 HTTP/2 连接，新请求通过新接口重新建连。已发送的数据不会在另一路径自动重放。在本机回环中，测试覆盖了 iOS 隧道和临时测速配置、多个探测共用一个入口、接口更新后重新拨号、真实目标首字节的计时。

## FastCat v2 的 HTTP/3 入口

同一程序的 `h3-server` 子命令监听 UDP。它通过 HTTP/3 CONNECT 建立 TCP 隧道，用扩展 CONNECT 的 `connect-udp` 协议和 HTTP Datagrams 转发固定目标 UDP 包。每个目标有独立请求流，传输共享已验证的 QUIC 连接。客户端首包在认证及目标接通后才发送。连接按需建立，空闲协商上限为 60 秒，默认不发送定时保活包。

```sh
fastcat-h2 h3-server -listen 0.0.0.0:18444 \
  -cert /etc/fastcat/fullchain.pem -key /etc/fastcat/privkey.pem \
  -tokens-file /etc/fastcat/h3.tokens -max-tunnels 128
```

为该 UDP 端口开放相应入站规则。向 HTTP/3 进程发 SIGHUP 可重载独立的设备凭据文件 `h3.tokens`；每个新 TCP 隧道和每个 UDP 关联都须重新通过授权。过期、移除设备和对后续请求的撤权规则与 HTTP/2 入口一致。已建立的流最迟受 `-session-timeout` 限制。仅以回环地址监听时可显式开放私有目标测试。生产入口解析并检查所有目标地址，只连接已经过策略验证的数值地址。

默认 URI 模板为 `https://{代理地址}/.well-known/masque/udp/{target_host}/{target_port}/`。客户端与服务端均要求 QUIC DATAGRAM 和 HTTP/3 Datagram 设置已协商，通过 Context ID 0 传送每个 UDP 包。发送端使用不可靠数据报，接收端也处理 DATAGRAM Capsule。丢失数据报由应用自行处理。单个数据报受实际 QUIC 路径 MTU 限制。

使用 `-tls-key-exchange x25519` 或 `-tls-key-exchange x25519mlkem768` 可以约束测试入口的握手组；生产未指定时沿用 TLS 库默认协商策略。可用 `go test -race ./verify -run TestH3Gateway` 验证 QUIC 连接复用、TCP 半关闭、UDP 数据报边界、严格证书校验和撤销授权。

## HTTP/3 服务入口的授权

`h3-server` 使用 `-tokens-file` 指定 HTTP/3 的独立令牌文件。单令牌验证可通过 `FASTCAT_H3_TOKEN` 配置；HTTP/2 的单令牌由 `FASTCAT_H2_TOKEN` 配置。设备级部署与热重载流程见 [Linux 部署说明](../../docs/fastcat-v2-linux.md)。
