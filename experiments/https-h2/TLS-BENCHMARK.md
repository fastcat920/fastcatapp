# FastCat v2 入口握手对照

`tls-key-exchange` 可取 `default`、`x25519` 或 `x25519mlkem768`。省略时沿用各传输库的默认协商行为。做经典组对照时必须显式指定 `x25519`。选择混合模式时，如果对端只允许经典组，连接将失败。两条路径都校验入口主机名、证书链和 ALPN。

HTTP/2 与 HTTP/3 客户端在显式对照模式下使用相同的 TLS 实现。连接诊断读取握手完成后的 `gateway-tls-version`、`gateway-cipher` 和 `gateway-group`。复用物理连接的请求可以读取该连接实际协商的参数。旧 Go 标准库无法读取默认路径的协商组时会省略该字段。显式模式在 Go 1.20.14 与 Go 1.26.2 均已通过真实 HTTP/2 CONNECT 测试。

## 荣耀 Android 12

2026-11-19 在已连接的 ARM64 手机上使用 Go 1.26.2 执行本机回环对照。每行 31 次独立连接，每轮交换两种模式的顺序，所有握手均完成域名及证书验证。手机上四组实际协商的都是 TLS 1.3 和 `TLS_CHACHA20_POLY1305_SHA256`。

| H2 / TCP | X25519 | 11.028 ms | 13.545 ms | 314 | 673 |
| H2 / TCP | X25519MLKEM768 | 14.664 ms | 19.013 ms | 1498 | 1761 |

## 复测

从工作区进入 `core` 后执行以下命令。工具仅监听本机回环，为本轮在内存中创建临时 ECDSA P-256 证书及相应的信任根，不读取设备凭据。

```sh
go run ./tools/fastcat-handshake -samples 31
```

H2 从 TCP 已接通后开始计时，客户端与服务器均完成 TLS 握手时停止。H3 从 QUIC 拨号到双方完成握手。这两个起点适合在各自传输内比较密钥交换选项。客户端计数分别是 TCP 套接字上的 TLS 字节、UDP 套接字上的 QUIC 数据报载荷（包含 QUIC 填充、分帧及计数截止前处理的 ACK）。采样排除 IP/TCP/UDP 头、连接关闭和 HTTP 请求。证书、包填充和 ACK 时序均可能改变大小。这个实验未测公网 RTT、完整网页首包、设备功耗或网络识别概率。

### Mac H3 慢握手定位与初始报文优化

在同一独立公网入口对每种模式交替测两轮，每轮 48 次。客户端 qlog
显示，部分慢样本发生在服务端 CRYPTO 数据到齐前。例如一条 ECH 流
约 110 ms 收到前两个 Handshake CRYPTO 分段，约 438 ms 发出 PTO
探测，约 933 ms 收到剩余分段后即完成 ALPN。另有样本在 Initial 阶段
触发重发。慢样本也见于基线。客户端日志无法区分异常分段究竟在哪一段
网络丢失或延迟，不能从这些数据认定 MTU 或 ECH 密码运算是根因。

### 三端共享的入口 DNS 优化

macOS、安卓和 iOS 的共享核心现在通过 DoH 并行查询入口地址和 HTTPS
记录。网关拨号仍需同时具备有效地址和 ECH 配置。直连 IP 只查 HTTPS
记录。地址查询仍优先 IPv4，在没有 A 记录时查询 AAAA。

本地集成测试要求两种 DNS 查询都已进入服务端后才能返回任一响应，覆盖
H2/H3 连接、DoH 瞬断重试以及缺失或不匹配的 ECH 配置。macOS 与安卓
真机核心测试通过，iOS arm64 核心完成编译。本次未重新安装三端 App，
也没有复测公网首字节 P95。macOS 的 1200 字节 H3 Initial 优化仅在
macOS 的 ECH 路径生效，移动端继续使用默认大小。
