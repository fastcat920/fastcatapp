# FastCat Next / FCN/1 原型规范 0.1

状态：独立实验原型，不是生产发布版。它定义新的隧道消息与生命周期，不重新发明 TLS、QUIC、AEAD 或拥塞控制。未经互操作、安全审计或跨网络长期测试，不能宣称不可识别。

## 1. 目标与边界

- TCP 主路径：独立 QUIC 双向流；UDP：QUIC DATAGRAM；TCP 备用：真实 HTTP/2 POST 双向流。
- 复用入口握手，合并授权和目标 OPEN；不保留 v3 的 Noise 握手、应用层多路复用、独立信用窗口和逐记录二次加密。
- 入口必须验证域名与证书。TLS 在受信任的节点端终止。前置仅做四层转发。
- 用户仍以账号授权。原型使用随机账号标识和 256 位随机密钥的静态映射。动态撤销、套餐控制、面板与计费适配是后续工作。
- 0-RTT 关闭。提交过的业务不自动重放。目标错误与认证错误不作为网络线路质量样本。

## 2. 公共安全上下文

TLS 最低版本 1.3，密码套件与密钥交换遵循 TLS 实现的默认协商。TLS exporter label 为 ASCII `EXPORTER-FastCat-Next-1`，context 为空，输出 32 字节。

HTTP/2 使用 ALPN `h2`；原生 QUIC 使用实验 ALPN `fcn-lab/1`。后者具有可见的实验特征，不能描述为浏览器 HTTP/3。此次不启用 ECH，也不声称继承 v2 已做的 ECH 验收结果。正式握手隐私适配必须单独验收。

认证证明：`HMAC-SHA256(account_key, label || exporter || open_without_mac)`。密钥恰为 32 字节，证明恒定时间比较。不同物理 TLS 连接必须重新计算，不能搬用上一连接的证明。

## 3. OPEN 消息

整数均为网络字节序。一个业务流仅允许一条 OPEN，随后全部字节是业务载荷。

| 字段 | 长度 | 约束 |
| --- | --- | --- |
| length | 2 | 后续 OPEN 长度，上限 512 |
| version | 1 | 1 |
| kind | 1 | 0 TCP；1 UDP 关联，仅 QUIC |
| account_length | 1 | 1..64 |
| account | 可变 | 不透明账号标识 |
| target_length | 2 | 1..255 |
| target | 可变 | host:port，IPv6 采用方括号，端口 1..65535 |
| nonce | 16 | 每次 OPEN 使用密码学随机数 |
| proof | 32 | 上述 HMAC |

单个物理连接最多接受 4096 个不同 nonce；重复 nonce 拒绝，不清空旧集合继续复用。客户端到限后只为新业务建新连接。旧连接继续已有业务，连接集合上限 2，达到上限时显式返回错误而不是无界扩张。

服务端先解析并验证完整 OPEN，再拨目标连接。认证失败不得产生目标流量。域名解析的所有候选地址先验证，再用固定的数值地址拨号，避免验证后重新解析；默认禁止私网、回环与保留地址。TCP 候选最多两条并行、间隔 250 ms，总拨号预算 5 秒；迟到的连接必须关闭。

## 4. QUIC TCP

客户端完成 TLS 握手后打开双向流，发送 OPEN 后即可排队业务字节。服务端认证并连接目标成功，先发送一个状态字节，再透传业务数据：0 成功、1 认证/协议拒绝、2 目标失败。

客户端向应用暴露的 Read 首次先消费状态字节，错误时不把状态或错误载荷作为业务数据。Dial 返回可能早于目标连接完成，因此入口耗时不能直接与“等待目标连接后返回”的其他协议逐阶段对比；端到端首字节是可比指标。

认证前的载荷只可能进入受传输流控约束的接收缓存，不向目标转发。不存在“握手失败就重发首个请求”的行为。

发送方向关闭使用 QUIC FIN；读取取消与写入取消使用流 reset。一个流失败不得关闭其他流。普通应用 Close 同时取消其读写方向。

## 5. HTTP/2 TCP

固定路径 `POST /session`，Content-Type `application/octet-stream`；请求体为 OPEN 后接业务数据。HTTP/2 必须由有效 TLS 1.3 连接建立，不支持明文 h2c。

200 表示认证和目标连接都成功；404 表示不可用或授权拒绝；502 表示目标失败；503 表示容量不足。响应体只含业务字节，不含 QUIC 的状态字节。普通浏览器访问原型没有可用内容；生产 HTTPS 站点共用与路径伪装尚未适配。

客户端显式创建一个固定物理连接上的 http2.ClientConn，使用其 exporter。不得由透明重连替换 TLS 后仍带旧证明，也不得自动重试 POST。每条流的关闭只取消对应请求。原型 deadline 通过取消该 HTTP 请求实现，是流级硬截止，读/写截止不独立恢复。

H2 不模拟 UDP。若没有 QUIC 路径，UDP 明确不可用，不把实时数据偷偷改成可靠 TCP 传输。

## 6. UDP

每个 UDP 关联用一条 QUIC 双向控制流：kind=1 的 OPEN。服务端先建立固定目的地址的 UDP socket，将关联登记，再返回成功状态。控制流 EOF/reset、连接关闭或最长 10 分钟到期，都销毁关联。

QUIC DATAGRAM 内容为 `association_id:uint64 || payload`，association_id 为控制流的 QUIC stream ID。没有应用重传和分片。payload 上限 1100 字节；超限在写入前显式报错，接收超限丢弃。零字节 UDP 允许。该限制为原型保守上限，不能声称支持任意 MTU 的游戏或语音报文。

未知关联数据报直接丢弃，不能创建新 socket。客户端每个关联最多排队 64 个报文，满时丢弃；QUIC 自身拥塞控制仍适用。ReadFrom 目的地址固定，WriteTo 不得改向其他目的地址。

## 7. 资源与生命周期

- 初始流接收窗 2 MiB、最大 6 MiB；连接 3/15 MiB，与 v2 客户端一致，避免把增大窗口的收益误算给格式。
- 默认无业务空闲 60 秒关闭；不加周期性保活；握手和 OPEN 头部读取限 5 秒。
- 每连接最多 128 入站双向流；服务端全局 256 个并行业务，原生 QUIC 全局最多 128 连接。
- 原型每条业务/UDP 关联最长 10 分钟。生产需要可配置配额与连接寿命。
- 客户端发现旧 QUIC 连接关闭，或 H2 不再接纳新请求，下次 Dial 创建新物理连接；复用凭证但不复用 exporter/证明。
- Reset 代表网络代际变化：显式关闭旧代际，后续新业务重新拨号。原型不承诺已有连接跨网无损迁移。
- Close 必须关闭 UDP socket、TLS 连接、关联及对应请求，不留下保活客户端。

## 8. 拥塞控制与实验

默认保留库原有 Reno；实验可选同一 Mihomo BBR 实现（标准 profile，初始 cwnd 32 包）。两端均切换才构成 BBR 组。接收窗口、证书、目标、账号权限及数据完整性校验保持一致。

原型性能测试强制指定 H2/QUIC，避免自动选路遮盖问题。正式自动选路、预建策略、交互/批量业务连接分组、ECH、按版本订阅、动态账号撤销和套餐计量均不得由此次单路径测试推定完成。

## 9. 验收

先做 v2 Reno/BBR 单变量，再与最新轻量版在同一安卓、网络、服务器和目标上交错测试。包括冷启动、三池连续、单池连续、4/8 并发、实际空闲时长、1 MiB 完整下载、8 秒单/四流完整性回环吞吐。

本地额外验证并发内容完整、半关闭、错误密钥不得拨目标、exporter 绑定、防重复 OPEN、畸形长度、原生 UDP/超限、空闲后新会话、显式代际重置、取消隔离和字节计量。

量化报告必须同时给样本数、成功数、P50/P95、失败阶段。原型测试可验收功能正确与本轮性能，不能验收 GFW 识别概率或长期耗电。
