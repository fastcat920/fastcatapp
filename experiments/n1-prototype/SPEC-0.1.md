# N1 原型规范 0.1

状态：原创应用层隧道原型；非生产版，已做内部审查、未做独立安全审计。不声称“全部层原创”或已降低 GFW 识别率。独立于 FCN v1/v2，不更改其节点。

## 目标与设计决策

先验证认证与记录层正确性、普通访问/错误认证的行为，再开展识别实验和性能优化。当前选用标准 TCP + TLS 1.3 + HTTP/1.1 全双工 POST 作为外层；没有自创密码算法，也没有借用 QUIC、REALITY 或 Vision 后重新命名。HTTP 双向流已有先例，不能将这部分宣称为原创。

原创内容限于本文定义的 capability 编码、会话绑定方式组合、双向记录格式与生命周期。尚不能证明与所有公开设计均不同。

## 字段及本版唯一配置

| 字段 | 本版选项 | 实际行为 |
|---|---|---|
| protocol | n1-lab-01 | 本规范的消息与生命周期 |
| entry | post-session-01 | 独立 TLS 入口，GET / 提供真实静态页面，认证后 POST 双向流 |
| authorization | bound-capability-01 | TLS exporter 绑定的 HMAC 目标授权 |
| records | sequence-length-01 | 序号、载荷长度、尾部填充、显式 FIN |
| traffic | bounded-tail-01 | 每条记录尾部 0..31 字节密码随机填充；只是实验基线 |
| recovery | fresh-session-01 | 每条新业务新建连接；不重放已有业务 |
| cipher | 标准 TLS 1.3 | 由 Go TLS 实现协商 AEAD；不是原创算法 |
| trust | CA + hostname | 正常链与名称校验，无 insecure 降级 |
| congestion | 系统 TCP 默认 | 未实现原创拥塞控制或 XTLS flow |

这些字段是规范结构，不是已实现的可任意切换的配置菜单。程序 JSON 还可配置有界建连重试、可选内存TLS缓存、显式网络代次和本地测试代理范围；这些是实现选项。

## 外层与授权

仅 TLS 1.3，ALPN http/1.1。每次创建独立 TCP/TLS 连接，不使用 TLS 0-RTT或外层连接复用；会话票据缓存默认关闭，可显式启用第九阶段的有界内存缓存。目标信息位于加密的 HTTP Cookie 中，不在 SNI 中。

认证请求：POST /api/events，Cookie session=base64url(capability)，Content-Type application/octet-stream，流式 chunked body。TLS 终止在实验服务端，不经过终止 TLS 的 CDN。

capability 无填充 Base64URL 解码后的结构：

| 字段 | 长度 |
|---|---:|
| Unix 秒时间戳，大端 | 8 |
| 密码随机 nonce | 16 |
| 目标字符串长度 | 1 |
| host:port | 1..255 |
| HMAC-SHA256 | 32 |

key 是随机 32 字节 PSK。exporter label 为 EXPORTER-FastCat-N1-Prototype，context 为空，输出 32 字节。MAC 输入为 `POST /api/events` + 单个零字节 + exporter + 前述未含 MAC 的完整 capability。

时间窗口 ±30 秒。每个节点最多保留 8192 个已验证 capability，60 秒后清理，满时拒绝新 capability。验证和去重完成后才能拨目标。允许管理员明确配置的数值 IP:port；第十阶段新增显式公共域名:数字端口名单并在实际连接时验证解析IP，拒绝私网/特殊地址。不开放任意转发。第十一阶段支持凭证轮换与撤销，未接入面板账号、订阅或计费。

不存在“错误认证回落到其他协议”。缺失/错误/过期认证、重复 capability、未授权目标与未知 POST 路径均返回相同的标准 404 状态和正文。不能据此推断时序、TLS 行为或所有主动探测均不可区分。容量不足返回 503；认证后目标拨号失败返回 502。

## 双向记录

HTTP 请求体及响应体各自承载独立序列的记录。所有整数大端：

`body_size:u16 | sequence:u32 | payload_size:u16 | payload | random_padding`

body_size 不含自身两个字节。载荷 0..16384 字节，填充 0..31 字节，由 crypto/rand 生成。序号从 0 开始严格递增，不允许回绕；零长度载荷为显式 FIN，因此本版不能把空记录当成业务消息。TCP 字节流本身不需要空消息。

传输 EOF 未收到 FIN 作为截断错误；不得当作正常业务结束。畸形长度、序号、载荷长度或填充边界立即结束该会话。TLS 提供完整性，记录层没有二次加密。

FIN 关闭该方向；服务端对目标执行 TCP CloseWrite，反向继续读取。目标先关闭其发送方向时，发送下行 FIN，但保留上行直到客户端 FIN 或会话超时；不得直接关闭目标的接收方向。一个会话只承载一个 TCP 目标，无多路复用、无 UDP、无动态调度。另一业务失败不应改变其他物理连接。

## 资源和超时

最大 HTTP 请求头 8192 字节，TLS/头部预算 10 秒；服务端最多 64 个已接入连接（含未认证）和 32 个并行业务。新增按服务端可见源 IP 的并发上限，默认8，可用 `-per-peer 0..64` 调整，0关闭此限制；IPv4映射IPv6地址归一化。同源额度满则在TLS前关闭新连接。连接关闭只释放一次额度，并移除归零计数。目标拨号5秒，每条业务最多2分钟；达到限制显式失败，不自动重放。

连接上限不等于完整抗资源耗尽设计，尚无账号公平性、带宽配额或分布式防护，不能直接面向不可信的大规模用户开放。同一NAT出口或前置服务器下的多个用户共享同源额度，默认8只是独立实验值，不是生产建议。普通网站仅最小静态页与32KiB合成资源，非完整站点伪装产品。自定义Cookie长度、Go TLS指纹、HTTP流及TLS记录/时间特征均可能被区分。

## 验证边界

本地覆盖：记录完整性、畸形/截断拒绝、TCP 半关闭、错误 key/目标/名称拒绝、TLS exporter 跨连接重放拒绝、过期 proof 拒绝。

公网用安卓独立原型进程验证，非完整快猫 App/VPN。目标是节点本机隔离测试源，不访问用户私有数据，不修改面板、订阅、计量或现有生产节点。第二阶段已补有限握手/记录对照、HTTP拒绝时序和单来源资源实验，详见PHASE2报告；真实App、UDP、切网、长期稳定、更多浏览器/网络及识别评估仍待验收。

## 第三阶段发送布局实验

服务端 `-emission legacy|coalesced` 控制相同N1线格式的发送实现，不改变授权、加密、记录长度、序号或填充范围。CLI仍默认legacy，实验节点可明确选择coalesced。

- 授权成功200必须立即输出，不等待目标载荷，避免应用等待Dial/CONNECT而目标等待请求的死锁。
- coalesced在一次TLS明文Write中组织完整HTTP chunk边界与一个N1记录；FIN记录与HTTP响应终止chunk同批输出，不增加定时等待。
- 接管HTTP/1.1连接后，仅复制已缓冲字节，随后用独立Reader及标准chunk解码器读取，不再使用原Request.Body。当前发送端无HTTP trailers；接收端拒绝非空trailers。
- N1 FIN与HTTP EOF分别验证。CloseWrite等待整个HTTP请求写入完成；双方业务正常结束后，有界完成外层EOF及TLS关闭流程再关闭底层socket。关闭阶段总预算5秒，且不超过会话截止时间；取消未完成业务直接中断。
- 接收FIN后重复Read保持EOF；写入FIN后禁止后续业务数据，重复FIN不再次发送。
- 诊断工具从本阶段起额外验证N1 FIN、外层HTTP响应EOF以及TLS终止读EOF。Go TLS在记录边界可能接受无close_notify的底层EOF，因此该EOF观察不单独证明收到了对端close_notify；本实现双方均调用TLS CloseWrite发送关闭通知。

本阶段full_request_ms包含新增关闭验证，不能直接与前两阶段仅完整HTTP响应的耗时作性能比较。

## 第四阶段测量接口（非 N1 线协议）

`workload` 模式对 N1、普通 HTTPS GET、服务端流式 RPC 使用相同的确定性载荷生成和有界节奏。比较指标为首个业务字节 `first_payload_ms`；RPC 提前确认头不能当成业务首包。所有响应逐字节校验，并检查消息结束及有界 TLS 终止读。

普通对照的可变资源和 `/api/sample-stream` 仅在显式 `-workload-controls` 时启用，默认关闭。每份公共载荷最大 1 MiB、每块最大 16 KiB、间隔最多 50 ms、总主动等待最多 3 秒；请求体最多 512 字节。这是合成实验服务，不代表真实浏览器或所有网站行为。内部回环测试源保留最大 32 MiB，不能直接公开。

N1 的授权、记录格式、随机填充范围、TLS 策略和 coalesced 发送策略在此阶段未变。训练与未见尺寸验证方案预先写入 PHASE4-PLAN.md；实验分类结果不能解释为实际 GFW 识别率。

## 第五阶段客户端发送布局（可选）

客户端私有配置 `client_emission` 支持 `legacy`、`coalesced`；省略仍为 legacy，未知值在拨号前拒绝。与服务端 `-emission` 独立，四种组合保持线协议兼容。

coalesced 用标准库生成并验证请求头，立即发送。每次业务 Write 立即组织完整 HTTP chunk 与 N1 记录；FIN 与外层 HTTP 终止 chunk 在同一次 TLS Write 中输出。没有定时等待、跨业务聚合、FIN 省略或重放。它移除 legacy 中单独发送的 `0\r\n\r\n`，并非移除该结束标记。客户端无需原先逐连接的 io.Pipe/请求写入协程；正常结束仍等待对端 N1 FIN、HTTP EOF 和有界 TLS 终止读。

本地写入观察只记录调用长度与帧类别，不记录 Cookie、目标、业务内容或密钥。观察到的明文 Write 与公网加密 TLS 记录分别验证，不假设一个 Write 在所有载荷尺寸下都恰好对应一条 TLS 记录。

## 第六阶段匹配对照（非 N1 协议）

`workload -kind matched-n1` 仅在合并客户端路径记录三次请求写入的长度与分块体长度；不输出内容。`matched-rpc -match-shape header,data,end` 构造普通 JSON 流式任务：确认头后上传带空白的 JSON 命令，接收完整数据后上传数字 0 作为完成回执，再结束 HTTP 上传。命令/回执分别匹配已观测的 N1 DATA/FIN 帧体长度，头部用有界应用元数据补齐，三个完整写入长度逐项一致。

对照不使用 N1 记录、授权、exporter 或目标转发。公共 `/j` 仅在 `-workload-controls` 时启用；命令最多 512 字节、回执最多 39 字节，输出与等待限制沿用 workload，连接总预算 30 秒。因 HTTP 劫持，仅读取脱离 net/http 生命周期的独立分块 Reader。

`-trace-writes` 只有与 `-workload-controls` 同时开启才记录服务端响应头、N1 记录/FIN、RPC 数据/结束等阶段及长度；不记录目标、Cookie、载荷、IP 或 TLS 密钥。默认关闭，实验后恢复原服务器。写入元数据在成功样本中与 TLS 记录重组核对，不能单凭一次调用断言实际发包数量。

这是一种有意匹配的合成对照，不代表真实网站的流量分布。只匹配上行长度和因果阶段，不匹配加密内容、精确时序或下行业务封装。每对 N1 必须先执行以取得长度，因此不作速度优劣结论。

## 第七阶段下行完整写入限额（实验选项）

新实验服务端支持 `-data-write-limit 16384`，仅与 `-emission coalesced` 一起使用；默认 0 维持原实现。发送端从目标读取 DATA 时使用最多 16337 B 的缓冲，为 N1 头 8 B、最大填充 31 B 和 HTTP chunk 边界 8 B 留出空间。编码后再次检查整次业务 Write 不超过 16384 B，超出则失败，不截断或丢弃。

接收格式和 16384 B 协议载荷最大值不变，上行客户端不受此参数影响；每条记录仍有独立序号和原随机填充，FIN 与 HTTP 结束标记仍发送和验证。没有定时等待、额外填充或重放。不限制 TLS 自身握手写入，也不保证早期自适应 TLS 记录不会继续拆分。

新增 `payload_read_ms` 为目标 HTTP 头之后的正文读取和校验耗时，含等待及已缓冲数据，排除入口建立阶段；`payload_read_mbps` 仅在完整载荷校验成功后输出。它不是纯线路速率，失败请求不按原请求大小推算速率。


## 第八至十一阶段的生命周期、安全与范围

- 分开记录DNS、TCP、TLS、认证响应头、目标响应头/正文、上行FIN、下行FIN、HTTP EOF和TLS终止EOF。完整正文、完整协议生命周期、观察到关闭EOF是不同指标，不互相替代。
- 服务端TLS/请求头预算默认10秒，可选5..20秒；本轮实验明确15秒，覆盖客户端12秒TLS预算。总请求预算仍有界。建连上下文取消不再中断已建立的业务，已建立业务仍有2分钟硬上限。
- `setup_attempts`默认1，可选2，仅在认证HTTP尚未发送之前对超时/EOF/重置重试一次，间隔150ms。证书失败、HTTP拒绝、已发送业务不重试或重放。
- `session_cache_size`默认0，可选8。最多16个配置，每配置8张票据、最多1分钟；绑定入口/域名/CA内容/曲线/网络代次/凭证摘要。内存缓存、不落盘、无0-RTT；恢复TLS仍须重新完成应用授权。
- 首版业务为TCP网页。UDP明确暂缓；不新增外层多路复用、部分业务恢复、自动重放。目标HTTP/2可在单目标字节流内部复用，这不是N1外层多路复用。
- `-public-targets`仅实验管理员提供，最多16项公共域名:数字端口。DNS在实际拨号地址处校验，拒绝私网、回环、链路本地及特殊地址；显式数值目标仍由管理员完整指定。该策略不是完整生产出站防火墙。

### 凭证环与撤销

`-credentials-file`指向不超过8192字节、当前进程所有、仅所有者可读写的普通JSON文件，拒绝符号链接。包含严格递增的正整数`revision`及1..4个`keys`。每个条目有内部`id`（1..32位ASCII字母数字下划线短横线）、32字节十六进制`key`、Unix秒`not_before`/`not_after`、布尔`disabled`。ID不增加到线上消息，不发送原始key。禁止重复ID或相同密钥（包含十六进制大小写等价）。有效期为左闭右开。

SIGHUP加载完整新版本；完全相同的同版本文件允许幂等，回退版本、同版本改内容、格式/权限错误均拒绝并保留最后有效版本。初始化失败直接退出。全部禁用是合法拒绝所有状态；只要指定凭证环，就永远不回退到旧配置的单PSK。

新连接以四次MAC验证（不足四项填充不可授权的dummy槽）检查当前有效凭证。认证之后、拨目标之前再次检查并登记有界活动租约，封闭认证/撤销竞态。删除、禁用、更换密钥或到期将取消对应租约并关闭入口/目标连接；过期后台检查周期1秒。SIGHUP更新撤销立即执行，实际客户端看到断开还受网络传递影响。正常释放租约不抢先关闭尚待FIN/HTTP结束的连接。

这提供实验凭证生命周期，不等于多租户账号体系或生产密钥管理系统。原型没有独立密码审计、账号公平调度、套餐计量、跨实例一致撤销或高可用控制面。部署前必须进行进一步评估。
