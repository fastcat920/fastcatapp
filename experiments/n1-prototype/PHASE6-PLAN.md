# Phase 6 predeclared matched-control validation

Scope: synthetic, deliberately matched normal streaming job, not a claim about prevalence of real websites or GFW detection probability. No N1 wire/emission changes this phase.

- 24 sequential pairs / 48 cold connections. Train response sizes 2048/20480/81920 B, held-out 4096/40960/163840 B. Each size x burst (16384 B, no gap) / paced (4096 B, 12 ms) x 2 repeats.
- Pair order randomized within split using seed 20261126 + split index. Within each pair N1 is necessarily first, followed by control replaying its nonsecret lengths; latency order is confounded, no speed superiority claim.
- For every pair: observe actual coalesced N1 plaintext request writes (header/DATA/FIN plus outer end); ordinary JSON job command and completion receipt have matching body bytes and complete write lengths. Header length is equalized by bounded application metadata. Acknowledgment headers precede upload command, upload remains open during all output, receipt/FIN follows verified output EOF. RPC uses no N1 records or proxy forwarding.
- Matching is by byte lengths and causal phases, not exact wall-clock schedule, cryptographic contents, cookie semantics, hidden TCP segmentation or downlink application format. Output byte values and source pacing match; N1 includes target HTTP framing absent from raw RPC data.
- Fit one-level decision stumps on training only: counts-only (client/server encrypted record count and <=256-byte count), all (plus log unique client/server TCP payload bytes), and upstream-only (client count/small-count/log bytes). No true size, IP/port, labels, trace IDs or timestamps as features. Report held-out confusion matrices; no feature/threshold changes using held-out results.
- Trace server plaintext write stages and lengths only while controls+trace-writes enabled. Events occur at attempted successful-path writes; on errors do not count as proof of complete emission. Compare small plaintext chunks (<=239 B predicts <=256 B encrypted record only when unfragmented, TLS1.3 tag/inner type +17 B) with captured encrypted records. Do not decrypt or export TLS keys, auth or content. Protected handshake/close records must not be attributed to app framing without evidence.
- Capture 48 unique chronological ClientHellos, require SYN, complete contiguous bidirectional reassembly, zero unparsed TLS tails, exact payload and ending checks. Stop/preserve failure, no quiet retries. Exclude pilot requests before capture.
- Disable public diagnostic controls and trace logging after capture. Restore prior Phase4 server binary and stable coalesced service, verify new client still interoperates. No APK, panel or production node changes.
